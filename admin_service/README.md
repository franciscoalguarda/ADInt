# Admin Service

The Admin Service is an independent Flask application for scheduling exams,
listing scheduled exams, bulk-enrolling students, listing enrollments, and
requesting printed resolution sheets.

## Run

Install Flask and SQLAlchemy in the project environment, then run:

```powershell
python -m pip install -r admin_service\requirements.txt
python admin_service\as_app.py
```

The service listens on `http://127.0.0.1:5002` and stores its database in
`admin_service\admin.sqlite`. It does not share a database with the User or
Printing Service.

Configuration:

- `ADMIN_DATABASE_URL`: SQLAlchemy database URL (defaults to the local SQLite file).
- `ADMIN_PRINTING_RPC_URL`: XML-RPC endpoint (defaults to
  `http://127.0.0.1:5003`).
- `ADMIN_SECRET_KEY`: Flask session key; set a private value outside development.

## Pages

- `/exams/schedule`: schedule an exam with course and date; the integer ID is
  generated by the database. The date must be today or later, based on the
  server's local date. Past dates are rejected without saving the exam.
- `/exams`: list exams, link to enrollment, and submit an order for printing.
- `/exams/<exam_id>/enroll`: bulk-enroll students from a UTF-8 CSV.
- `/enrollments`: list enrollment details (exam, date, course, and student ID).

The CSV must contain a `student_id` column, with one positive 64-bit integer per
row (at most `9223372036854775807`).
`student_identifier` is accepted as an alternative header. An upload is atomic:
invalid IDs, repeated IDs, or students already enrolled cause the entire upload
to be rejected. Rows with missing or extra fields and malformed CSV quoting
are reported in the form without saving any enrollments. Additional columns
are accepted when declared in the header.
Because user records live in a separate service/database, this
service stores the supplied student IDs but cannot verify that those users exist.

## Printing Service XML-RPC contract

The Admin Service calls the XML-RPC method `print_exam` with four positional
arguments: `exam_id` (decimal string), `exam_date` (ISO `YYYY-MM-DD` string),
`course` (string), and `student_ids` (list of decimal strings). Identifiers are
stored as integers in SQLite; decimal strings are used only in the XML-RPC
request to preserve 64-bit values beyond the protocol's 32-bit integer limit.
The Printing Service also accepts integer arguments from existing clients.
The Printing Service implements this contract at `http://127.0.0.1:5003` by
default. Configure its endpoint with `ADMIN_PRINTING_RPC_URL` if needed. A
failed RPC is reported to the administrator; it is not recorded as a successful
order.

Each exam is assumed to have four questions, as specified in the project brief.
The Printing Service produces a single PDF with four pages per enrolled student
and a unique QR-code identifier on each resolution sheet. See
`printing_service\README.md` for setup and configuration.
